# LAN Apps

Both launch only from menu and release on exit; no boot service. Web UI address uses current rtlwlan0 IPv4, port8080. Screen displays username admin and fresh eight-hex-digit password each launch; no persistent weak default. HTTP Basic is not encrypted: trusted LAN only, do not expose through DDNSTO/public forwarding. F1_WEB_PASSWORD supports6..16chars for isolated tests/explicit configuration. Browser401 prompt requests login. Upload multiple files sequentially with progress/cancel; files stored only /root/roms/Uploads and downloadable there. Existing files rejected,2GiB max,32KiB IO buffers, one worker; invalid path/control/symlink rejected. .upload-PID temporary removed on orderly failed/canceled uploads. Abrupt power loss can leave hidden .upload file; not automatically delete unknown files.

DLNA menu publishes F1C200S-DLNA on rtlwlan0 only. Complete GMediaRender/pupnp SSDP/SOAP/eventing implementation; no hand-written protocol engine or GStreamer/SDL. Output uses existing /root/roms/candidates/mplayer_geometry_20261005/mplayer-native-geometry, HTTP/HTTPS URIs only, H264 MP4 and supported MPlayer audio. No transcoding/DRM/DASH promise. Native hard decode/90deg rotation, normal ALSA routing. Remote Play/Pause/Seek/Stop/volume/mute. Waiting page has exit button, released before player; remote Stop brings it back. During playback three center releases in2seconds exit application via raw evdev monitor; physical gesture pending. UI and video never draw concurrently. No automatic interruption of Miracast because app menu already serializes ownership. Fixed rendererUUID appropriate for this one board, change if cloning to multiple devices.
